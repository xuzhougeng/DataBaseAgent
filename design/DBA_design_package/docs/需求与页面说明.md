# DBA 需求与页面说明

## 产品目标

DBA 是本地运行、按项目管理的主题数据库构建智能体。用户可以同时开展多个数据库项目，每个项目有独立的主题、检索策略、复核结果、处理流程和数据产物。

核心流程为：确定主题 → 构建偏宽的检索策略 → Agent 复核并提示用户检查 → 用户确定处理工具与流程 → 自动下载与远程处理 → 结果同步本地并用于后续建库。

用户为 DBA 配置服务器资源；DBA 调度远程计算，定期检查进展并处理可恢复的问题。重复失败或无法可靠判断的问题转为求助，处理后继续推进。

| 页面 | 核心内容 | 原型入口或交互 |
| --- | --- | --- |

| 处理流程 | 工具、参数、服务器、资源与并发配置 | 解锁编辑、锁定、创建演示任务 |
| 运行任务 | 任务状态、进度、服务器、运行日志 | 筛选、搜索、详情、补充分组 |

## 布局与视觉

左侧固定导航负责项目切换和工作阶段定位；中间为主要内容；右侧展示 Agent 动态、待处理求助及指令输入。浅灰绿色背景搭配白色卡片，绿色表示主要操作与正常状态，橙色提示人工关注，红色表示异常。

源文件中的 CSS 变量包括背景 `#f6f8f9`、主文字 `#20332f`、边框 `#e6ece9` 和主绿色 `#237c63`。字体采用 Inter、苹方、微软雅黑及系统无衬线字体回退；文件不加载外部字体。图标由内嵌 SVG 路径绘制。

## 关键交互约定

**人工复核**：展示 Agent 结论及依据，由用户决定是否纳入。应保留判断和用户操作记录，避免只有结果而无法回溯证据。

**流程锁定**：用户确认分析工具、参数和资源后锁定版本。未来真实运行应绑定该版本，确保任务具有明确的执行依据。

**自动恢复与求助**：断点续传等可恢复错误可按重试策略处理；样本分组不明等涉及科研判断的问题展示证据和已尝试动作，等待用户补充。原型用补充分组弹窗展示这一交接过程。

**远程处理与本地归档**：服务器保留原始数据及大型中间文件，本地同步分析结果和元数据。原型展示增量传输、SHA-256 校验和结果索引的预期流程。

## 后续开发衔接建议（尚未实现）

以下内容用于把页面原型衔接到真实应用，不代表已完成的系统功能。

| 模块 | 建议承担的职责 |
| --- | --- |
| 本地项目存储 | 保存项目、检索记录、复核结论、配置与审计日志 |
| 检索与元信息适配器 | 按来源检索、去重、关联文献与原始数据编号 |
| 复核 Agent | 根据项目标准提取证据，形成可追溯的建议 |
| 流程注册与版本管理 | 保存工具、容器、参考数据、参数及输入输出契约 |
| 远程执行器 | 连接 SSH 或调度系统，提交任务并收集日志和状态 |
| 巡检与恢复机制 | 检查心跳、分类失败原因、有限重试及转交求助 |
| 同步与产物索引 | 增量传输、校验、归档并建立可供数据库读取的索引 |

建议至少区分项目、候选数据集、人工复核记录、流程版本、执行任务、服务器资源、求助事件和产物清单。任务关联其输入、流程版本、服务器和产物，复核和修复动作保留时间及理由。

原型已有数据契约示例：`dataset_id`、`source_accession`、`organism`、`perturbed_gene`、`perturbation`、`sample_groups`、`pipeline_version`、`output_files`、`review_decision`、`run_provenance`。其中扰动相关字段适用于 GPSA 示例；其他主题应按项目扩展。

开发时先贯通“单项目、单数据集、单服务器”的真实处理闭环，再扩展多项目调度。页面中的演示工具及版本仅作为占位配置，实际选择由用户定义，并以实际执行环境为准。
